# Mud
Mud (because Clay for was taken) is a UI layout library built in C. The design philosophy of Mud is to provide the tools for handling UI layout and events, along with an API for a rendering backend to use to render a layout generated by Mud. 

## Workflow 
A typical workflow for a Mud application goes as such:
```c
MudBackend_Options backend options = { ... };
int main(void) {
    Mud_App app = { 0 };
    // Initialize the Mud library and the backend
    Mud_AppResult result = Mud_init(&app, &backend_options);
    if (result != MUD_CONTINUE) return EXIT_FAILURE;

    // Set the initial scene (user defined function, not part of the Mud API)
    setInitialScene(&app, ...);
    
    // Set the main app loop to handle events and then render the app
    while (result == MUD_CONTINUE) {
        result = Mud_handleEvents(&app);
        if (result == MUD_CONTINUE)
            result = Mud_render(&app);
    }

    Mud_terminate(&app, result);
    return EXIT_SUCCESS;
}
```
All the render code and event handling code are in function pointers which are passed to the `app` struct through the `setInitialScene` function. The `app` struct can then be modified through events, until the app terminates.

## Mud API
### App
The `Mud_App` struct is the struct that will be passed to every function in the app. This means that this struct contains all the information necessary to render the app and handle events.
```c
struct Mud_App {
    // All data needed for rendering the app
    Mud_Render render;
    // To avoid unnecessary renders
    atomic_int rerenderLayoutNextFrame;

    // Layout and event information for RenderBoxes
    Mud_Scene scene;

    // Global events and mouse state
    Mud_AppEvents events;
};

```

### Layout
#### Scene
The main layout of the application is contained in the `Mud_Scene` struct. A scene has an ID, a function to compute its layout, rendering information, custom data and a function to free the memory owned by the `Mud_Scene`. 
```c
typedef struct Mud_Scene {
    Mud_SceneId sceneId;
    Mud_Layout sceneLayout;

    ComputeSceneLayout computeSceneLayout;
    TerminateScene terminateSceneFunction;
    void* data;
} Mud_Scene;
```
The `Mud_Layout` struct contain the background color and an array of `Mud_LayoutBox`.
```c
typedef struct Mud_Layout {
    Mud_Color bgColor;
    Mud_LayoutBox* layoutBoxes;
    size_t numLayoutBox;
} Mud_Layout;
```
Each `Mud_LayoutBox` contains information about its position, rendering and event handling. There is also a `isActive` parameter, which handles if the layout box is rendered and its events are handled.
```c
typedef struct Mud_LayoutBox {
    bool isActive;
    Mud_Rect renderRect;
    Mud_RenderFunction renderFunction;
    Mud_EventCallback onMouseButtonDown;
    Mud_EventCallback onMouseButtonUp;
    Mud_EventCallback onMouseEntered;
    Mud_EventCallback onMouseHovered;
    Mud_EventCallback onMouseExited;
    Mud_EventCallback onMouseWheelScrolled;
} Mud_LayoutBox;
```
The render function can use Mud primitives to draw things to the screen.
```c
typedef enum {
    MUD_PRIMITIVE_BORDER_QUAD,
    MUD_PRIMITIVE_FILLED_QUAD,
    MUD_PRIMITIVE_TEXTURED_QUAD,
    MUD_PRIMITIVE_TEXT
} MudPrimitiveType;
```
To add a primitive to the layout, you can use the function `Mud_addPrimitive` with a parameter of a struct representing the primitive. Each primitive has different parameters which determine their position, size, type, color, texture or text if applicable.

Each primitive is added onto a render queue managed internally by Mud. Mud will then call specific functions which the rendering backend can implement. This is the most important design decision of Mud:
- Mud defines *what* can be drawn
- The backend defines *how* it's drawn

### Events
Events are put in a queue and all events are handled when the function `Mud_handleEvents` is called. This function will dispatch events to all callbacks of the layout boxes and the global app events. This function will also update the mouse state. 

The global app events and mouse state are in the `Mud_AppEvents` struct.
```c
typedef Mud_AppResult(*Mud_EventCallback)(Mud_Event*, Mud_App*);

typedef struct Mud_MouseState {
    bool holdingLeftMouseButton;
    bool holdingRightMouseButton;
    Mud_Point mousePoint;
} Mud_MouseState;

typedef struct Mud_AppEvents {
    Mud_EventCallback onWindowResize;
    Mud_EventCallback onKeyDown;
    Mud_EventCallback onKeyUp;
    Mud_EventCallback onQuit;

    Mud_MouseState mouseState;
    atomic_int shouldHandleEvents;
} Mud_AppEvents;
```
The callbacks of events specific to a `Mud_LayoutBox` will only get called if the mouse clicked in the render rectangle of the layout box or if it is hovering the rectangle. This is the same of the mouse wheel, the mouse needs to be hovering the layout box 

### Rendering
The function `Mud_render` will handle the dispatching of Mud primitives to the rendering backend. This function will also run if the `rerenderLayoutNextFrame` field in the Mud_App struct is set to `MUD_MAIN_THREAD_RERENDER` or `MUD_OTHER_THREAD_RERENDER`. Before this function returns, this parameter will be set to `MUD_NO_RERENDER`, which will disable the dispatching of the layout to avoid unnecessary rerenders of the UI. This is the logic of the `Mud_render` involving the `rerenderLayoutNextFrame` field.
```c
Mud_AppResult render(Mud_App* app) {
    // We only rerender if we are told so
    if (atomic_load(&app->rerenderLayoutNextFrame) == MUD_NO_RERENDER) {
        return MUD_CONTINUE;
    }
    else if (atomic_load(&app->rerenderLayoutNextFrame) == MUD_OTHER_THREAD_RERENDER) {
        // If we already have a MUD_OTHER_THREAD_RERENDER value then we don't want to rerender twice
        // so we set the value to MUD_MAIN_THREAD_RERENDER
        atomic_store(&app->rerenderLayoutNextFrame, MUD_MAIN_THREAD_RERENDER);
    }
    /*
        ...
        Logic for dispatching the layout to the rendering backend
        ...
    */

    // After we rerender, we assume that shouldRender is either OTHER_THREAD or MAIN_THREAD
    // This means that if shouldRender is MUD_NO_RERENDER then it will stay that way
    // else we go to a MUD_MAIN_THREAD_RERENDER so that we rerender once more before stopping
    if (atomic_load(&app->rerenderLayoutNextFrame) == MUD_OTHER_THREAD_RERENDER) {
        atomic_store(&app->rerenderLayoutNextFrame, MUD_MAIN_THREAD_RERENDER);
    }
    else {
        atomic_store(&app->rerenderLayoutNextFrame, MUD_NO_RERENDER);
    }

    return returnValue;
}

```
